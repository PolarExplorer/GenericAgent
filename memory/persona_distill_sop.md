# Persona Distill SOP

## Struct Header
- Reader: GA 总控 / subagent / supervisor
- When to read: 用户要求“蒸馏某人”“用某人物视角分析”“把某专家变成可复用 skill”时。
- Trigger: 蒸馏X / X视角 / 用X的方法看 / 让X帮我判断 / 生成X perspective skill。
- Inputs: 人物名、任务问题、资料范围、输出格式、是否写入长期 skill。
- Outputs: 人物认知框架笔记、可调用 perspective skill、调用模板、边界声明。
- Tools: web_access_sop, research_sop, writing_sop, skill_struct_header_sop, verify_sop。
- Side effects: 可能联网检索公开资料；经用户确认后可新增 L3 skill 文件并同步 L1 索引。
- Risk: R1/R2。禁止冒充本人、伪造本人观点、替代专业建议；公众人物/在世人物需标注“公开资料抽象，不代表本人真实意见”。
- Schedule: 需求界定 -> 资料收集 -> 证据分级 -> 五层抽取 -> 证据增强(L1→L2) -> 反例校验 -> skill生成 -> 最小调用测试。
- Failure path: 资料不足则降级为“初步画像”；证据冲突则保留分歧；涉及高风险决策时只输出思考框架。
- Review: 新增或修改长期 skill 前需验证文件存在、结构头完整、L1索引同步；敏感人物/高影响场景需提醒用户独立判断。

## 1. 目标

把公开资料中的人物长期思考方式，蒸馏成 GA 可复用的“认知框架 skill”。

此 SOP 不用于角色扮演，也不宣称代表本人；只抽象其公开表达中反复出现的判断模式、问题意识、取舍原则和盲点。

## 2. 输入澄清

执行前确认：

1. 人物是谁：真实姓名、别名、领域。
2. 使用目的：分析项目、学习解释、产品批判、写作风格、投资判断等。
3. 资料边界：公开互联网、指定链接、书籍/演讲/访谈、用户提供资料。
4. 输出形态：一次性分析 / 精读笔记 / 长期 skill。
5. 风险等级：是否涉及医疗、法律、金融、政治、声誉等高影响判断。

## 3. 资料收集原则

优先级：

- A：本人著作、演讲、访谈、公开信、论文、公司备忘录等直接材料。
- B：多来源交叉印证的可靠二手资料。
- C：单一二手资料或评论文章。
- D：模型推断、网文转述、不可验证说法。

长期 skill 的核心结论应尽量来自 A/B 证据；C/D 只能作为假设或待验证项。

## 4. 五层抽取框架

### 4.1 问题意识

此人最常把世界看成什么问题？例如：效率、复杂性、激励、体验、学习、工程瓶颈、制度约束。

### 4.2 底层信念

此人反复依赖哪些基本假设？例如：人性约束、第一性原理、复利、简单性、可证伪性、用户体验优先。

### 4.3 判断模型

面对问题时，此人会优先问什么、排除什么、比较什么、用什么标准取舍。

### 4.4 行动原则

此人会如何从判断走向行动：试错方式、资源配置、风险控制、组织方式、沟通方式。

### 4.5 盲点与反校验

该视角容易忽略什么？在哪些场景下不适用？哪些反例会推翻这个框架？

## 5. 证据增强阶段（L1 骨架 → L2 深度 skill）

§4 五层抽取产出的是 **L1 骨架**：结构完整但证据薄、案例少、判断模型停留在概括层。要让 skill 真正可用，必须走标准化的证据增强流程，而不是靠临时决定"要不要再查点资料"。

### 5.1 触发条件

完成 §4 五层抽取后，检查以下指标。**任一未达标**即触发本阶段：

| 检查项 | L1（骨架） | L2（可用） |
|--------|-----------|-----------|
| 核心信念 | 有列表但无出处 | 每条附 A/B 级证据来源 |
| 判断模型 | 概括性描述 | 有 if-then 决策树或 2+ 真实案例演示 |
| 行动原则 | 泛化表述 | 有具体场景 + 反例 |
| 盲点 | "可能不适用于…" | 有至少 1 个具体反例或失败案例 |
| 示例对话 | 无 | 至少 1 个完整 Q&A 展示判断过程 |
| 体量 | <4k chars | 8-14k chars |

### 5.2 标准化研究步骤

```
Step 1: 薄弱点定位
  - 逐层扫描 §4 产出，标记每个断言的证据等级（A/B/C/D）
  - 列出所有 C/D 级断言 → 这些是研究目标

Step 2: 定向检索（不是漫无目的地"多查点"）
  - 每个 C/D 断言生成 1-2 个具体检索 query
  - 优先找一手材料（本人著作/演讲/访谈/代码/论文）
  - 工具：web_access_sop, research_sop
  - 预算：每个断言最多 3 轮检索，找不到则标记"待验证"

Step 3: 证据整合
  - 找到的证据直接嵌入对应层级（不是堆在末尾）
  - 格式：在断言后附 [来源: 书名/演讲/链接, 证据等级: A/B]
  - 冲突证据保留双方，标注分歧

Step 4: 案例补充
  - 每个判断模型至少补 1 个真实应用案例（before/after 或 decision walkthrough）
  - 案例来源优先级：本人公开案例 > 可验证的二手描述 > 合理推演（标注）

Step 5: 示例对话生成
  - 基于已有证据，写 1-2 个完整示例对话
  - 对话必须展示：触发 → 判断过程 → 结论 → 边界声明
  - 禁止编造本人未说过的话；用"基于其公开表达的推演"

Step 6: 体量与质量自检
  - 目标：8-14k chars, 300-470 行
  - 每个核心断言有 A/B 证据支撑或明确标注"待验证"
  - 有决策树或 worked example 展示判断过程
  - 通过则进入 §6 生成最终 skill；未通过则回 Step 2
```

### 5.3 跳过条件

以下情况可跳过本阶段：
- 用户明确要求"快速画像"而非长期 skill。
- 人物资料极度稀缺（如非公众人物），§4 产出已是能力上限。
- 外部适配路径（§8）已提供高质量完整 skill，无需从 L1 升级。

### 5.4 产出物

本阶段完成后，应产出：
- 证据增强版五层抽取（每条附出处和等级）
- 1-2 个 worked examples 或 before/after 案例
- 1-2 个示例对话
- 待验证项清单（C/D 级断言未能升级的）
- 体量自检通过记录

这些直接作为 §6 生成最终 skill 的输入。

## 6. 生成 perspective skill 的标准结构

```md
# <name>_perspective_skill

## Struct Header
- Reader:
- When to read:
- Trigger:
- Inputs:
- Outputs:
- Tools:
- Side effects:
- Risk:
- Schedule:
- Failure path:
- Review:

## 0. 反拟人化声明

## 2. 核心问题意识
## 3. 底层信念

## 5. 行动原则

## 7. 盲点与反校验
## 8. 调用模板
## 9. 证据与待验证项
```

## 7. 调用规范

调用时使用：

> 基于 `<人物>` 公开资料抽象出的认知框架，从该视角分析……

不要使用：

> 我就是 `<人物>`；`<人物>` 一定会说……；这是 `<人物>` 的真实意见……

## 8. 外部案例适配路径

当外部已有高质量 perspective skill（如开源社区案例），可跳过从零蒸馏，走适配路径：

### 7.1 路径 A：合并增强（已有旧 skill + 外部案例）

1. 下载外部案例，通读全文，标记可合并模块。
2. 保留我方 GA 特色：Struct Header、证据等级声明、调用模板。
3. 从外部补入：角色扮演规则、心智模型、决策启发式、表达DNA、示例对话、身份卡、智识谱系、诚实边界。
4. 去重合并：我方旧内容若已被外部更完整版本覆盖，直接替换；独有内容保留。
5. 目标体量：10-14k chars，400-470行。

### 7.2 路径 B：外部直接适配（无旧 skill）

1. 下载外部案例原文。
2. 剥离原格式（如 YAML frontmatter）。
3. 添加 GA Struct Header（Trigger/Inputs/Outputs/Tone/Risk/调度）+ 证据等级声明。
4. 保留外部原文主体不做大改。
5. 写入 memory，git add -f（skill 文件可能被 .gitignore 忽略）。

### 7.3 适配后必做

- L1 索引同步（global_mem_insight.txt）。
- 桌面速查同步（GA_指令速查.md）。
- git commit。
- 最小验收（见 §10）。

## 9. 完整格式标准（当前标杆）

perspective skill 的完整格式应包含以下模块（参考 munger/naval/karpathy 等已有 skill）：

```
# <Name> Perspective Skill

## Struct Header（GA 特色，必须）
## 证据等级声明（GA 特色，必须）
## 角色扮演规则（沉浸式第一人称，退出机制）
## 使用说明（擅长/不擅长/盲区）
## 心智模型（5-6个核心模型，编号）
## 决策启发式（7-9条，编号）
## 表达DNA（句式/节奏/词汇偏好/禁忌）
## 示例对话（1-2个完整示例）
## 身份卡（一句话定位+关键标签）
## 智识谱系（影响此人的思想家/书籍）
## 诚实边界（不知道就说不知道的规则）
## 内在张力（此人思维中的矛盾/取舍）
```

旧版 §6 的 9 段结构（反拟人化声明/人物定位/核心问题意识/底层信念/判断框架/行动原则/适用场景/盲点/调用模板/证据）仍可用于从零蒸馏的初始版本，但长期 skill 应逐步升级到完整格式。

## 10. 最小验收

新增长期 skill 后至少检查：

- 文件存在且可读取。
- 含 Trigger / Inputs / Outputs / Tools。
- 含 Side effects / Risk / Failure path / Review。
- 含反拟人化声明。
- 含证据等级或待验证项。
- L1 索引含极简入口。
- git diff --check 通过并提交。
