# typed_memory_sop：类型化长期记忆治理

> 来源：arXiv:2604.22085 Memanto 阅读与本地实践抽象。  
> 定位：L3 SOP。用于决定“查什么记忆、写什么记忆、如何避免冲突和过期事实”。  
> 原则：No Execution, No Memory；未验证不入 L1/L2/L3。

## 1. 适用场景

在以下任一场景启用：

1. 任务需要依赖长期偏好、环境配置、历史故障、SOP、工具能力。
2. 用户要求“记住 / 落地 / 固化 / 写入 SOP / 形成 skill”。
3. 多次失败后需要从过往经验中找相似故障。
4. 修改 L1/L2/L3 记忆前需要判断写入层级、冲突和新鲜度。
5. 读取到的长期记忆可能随时间变化，例如 API 端点、依赖版本、路径、服务状态、用户偏好。

## 2. 记忆类型

写入或检索前，先把候选信息归入以下类型之一：

| 类型 | 含义 | 默认层级 |
|---|---|---|
| `user_preference` | 用户长期偏好、协作方式、禁忌 | L2；L1只索引 |
| `environment` | 本机路径、依赖、版本、服务、端口、安装状态 | L2 |
| `procedure` | 可复用步骤、工作流、SOP | L3 SOP |
| `skill` | 可直接调用的脚本/工具能力 | L3 `.py` 或 scripts |
| `constraint` | 硬约束、红线、触发条件 | L1索引 + 约束DSL/SOP |
| `failure_lesson` | 经工具验证的失败根因、修复、避坑 | L2或相关SOP |
| `project_state` | 某项目阶段状态、待办、交接 | project_board/session handoff |
| `external_fact` | 外部世界事实、论文/网页/API信息 | 任务产物；除非高复用，不入长期记忆 |

## 3. 检索策略：召回优先，再压缩

1. **先定类型**：判断本任务最可能需要哪些记忆类型。
2. **高召回检索**：关键词必须包含同义词/别名/文件名/错误码/工具名。
3. **分层读取**：
   - 先读 L1 `global_mem_insight.txt` 定位；
   - 再读 L2 `global_mem.txt` 或目标 L3 SOP/脚本；
   - 对代码/文件事实用 `agentic_search_sop` 的 Grep-first + 证据验证。
4. **证据标注**：输出关键决策时说明来自哪个文件/工具结果；无证据不得声称。
5. **压缩使用**：召回多条后，只保留和当前任务直接相关的约束、路径、命令、失败教训。

## 4. 写入策略：分类、验证、最小化

写入长期记忆前必须满足：

1. 已读取 `memory_management_sop`。
2. 信息来自成功工具调用、用户明确偏好或已验证产物。
3. 已分类到第2节的类型。
4. 已检查是否与现有 L1/L2/L3 冲突。
5. 写入最小必要内容，避免把任务流水账写入长期记忆。

层级选择：

- **L1**：只写导航索引和一句话红线；保持极简。
- **L2**：写稳定事实、用户偏好、环境状态、故障教训。
- **L3**：写可复用 SOP、脚本、工具模板。
- **L4**：原始会话和未蒸馏材料，不直接作为行动依据。

## 5. 冲突处理

当新旧记忆不一致时：

1. 不直接覆盖旧事实。
2. 记录冲突点：旧值、新值、证据来源、验证时间。
3. 优先级：
   - 用户最新明确偏好 > 已验证本机状态 > 旧记忆 > 模型推断。
   - 安全/合规约束优先于效率偏好。
4. 若无法验证，标为“待验证”，不得写成确定事实。
5. 修改已有 L2/L3 时用小范围 patch；避免整段覆盖导致丢失历史教训。

## 6. 新鲜度检查

以下类型默认时间敏感，使用前必须验证或标注更新时间：

- API 端点、模型名、依赖版本、命令参数；
- 本机路径、浏览器/服务/端口状态；
- 网站反爬、登录状态、验证码策略；
- 用户近期偏好和协作规则；
- 项目进度、部署状态。

若记忆超过任务可接受的新鲜度窗口：

1. 先用工具验证；
2. 验证失败进入 `debugging_sop`；
3. 不把旧值当作当前事实。

## 7. 任务入口清单

复杂任务开始前，快速回答：

1. 这次任务需要哪些记忆类型？
2. L1有没有相关索引？
3. 是否需要读 L2 或 L3 SOP？
4. 是否存在时间敏感事实，需要先验证？
5. 若要写记忆，证据来自哪里？会不会与现有记忆冲突？
6. 用户是在提问还是授权执行？疑问句默认只回答，不执行。

## 8. 工具配套

配套脚本：`typed_memory_utils.py`

建议用途：

```bash
python memory/typed_memory_utils.py classify "用户说以后疑问句只是在问意见"
python memory/typed_memory_utils.py plan "arXiv API 429 tabulate 缺失"
python memory/typed_memory_utils.py conflict --old "默认直接执行" --new "疑问句默认只回答"
python memory/typed_memory_utils.py freshness "PackyAPI GPT-5.5 endpoint"
```

工具只提供分类、检查和计划，不直接写入长期记忆；最终写入仍必须遵守 `memory_management_sop`。
