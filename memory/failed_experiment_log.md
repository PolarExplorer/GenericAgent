# failed_experiment_log.md — 失败实验日志

> 定位：L3 防踩坑记录。记录已执行但被回滚/放弃的记忆系统改动，防止重复犯错。  
> 来源：arXiv:2604.01007 OMNI-SIMPLEMEM "failed experiments are data" 思想。  
> 原则：失败≠浪费——结构化记录失败，就是在积累约束知识。

## 字段说明

| 字段 | 含义 |
|---|---|
| ID | 自增序号（F-001 格式，F=Failed） |
| 日期 | YYYY-MM-DD |
| 关联实验 | 对应 `memory_experiment_log.md` 的 ID（若有） |
| 假设 | 改动前的预期 |
| 改动类型 | 见 `memory_discovery_taxonomy.md` 的 6 类 |
| 做了什么 | 具体改动描述（极简） |
| 失败表现 | 发生了什么问题 |
| 根因分析 | 为什么失败（一两句话） |
| 教训/禁忌 | 未来应避免什么（可被提炼为约束条目） |
| 是否已转约束 | ✅ 已写入 rules_engine / ❌ 仅记录 |

## 使用规则

1. 触发条件：记忆系统改造出现失败修复、误判、回滚、放弃路径、无效实验，或 `debugging_sop` 进入阶段3但假设被证伪时，追加一条失败记录。
2. 记录粒度：只记录已执行且有证据的失败；未执行计划、模型猜测、单次未解释工具抖动不得写成确定教训。
3. 升层限制：失败记录默认停留在本文件或 L4；只有被后续复现、工具验证或多次观察支持后，才可提炼为 L2 故障教训或 L3 SOP 约束。
4. 复用要求：后续相似记忆改造前，先检索本文件；命中相似失败时，必须说明本次如何避免重复。
5. 转约束条件：当“教训/禁忌”已被写入 rules_engine、typed SOP 或相关 L3 SOP 时，`转约束` 才能标 ✅，并在备注/关联实验中保留来源。
